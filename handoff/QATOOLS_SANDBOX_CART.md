## Implementation

- New authenticated cart API validates only a list of unique product IDs. Prices, ownership, customer identity and Paddle IDs are resolved/validated on the server. Every published price is checked against Paddle immediately before reservation; subscriptions, discounts, price overrides, wrong currencies/tax modes, quantities or altered totals fail closed.
- New /admin Tool prices panel lets the owner load, verify and save a sandbox product/price mapping. Server independently checks admin membership and provider price. SQL checks the admin again and compares prior mapping state before saving. Mapping table and write RPCs are unavailable to browser roles. The existing verified qafit01 mapping is seeded; qarand01 must be created and connected by the owner.
- Immutable cart snapshots extend existing checkout intents. A shared ownership lock serializes overlapping reservations and grants. Reordered provider lines are supported; cart snapshots use sorted product IDs. Existing legacy attempts, event digests, order numbers and history remain. Old clients cannot race new cart reservations or purchase disabled/changed qafit01 mappings. Unresolved/overlapping creating, unknown and ready attempts are retained and require reuse or operator review; no age-based cleanup or automatic second transaction is introduced.
- A single signature-verified completed payment grants all order items and purchase entitlements in one SQL transaction after exact snapshot/transaction/price/product/amount checks. Any failure rolls back every grant and the transactional order counter. Browser success only refreshes entitlements. The browser checks the entire returned cart and total and confirms all purchased slugs.
- New transactions store provider transaction-item IDs for refund binding. Approved full tool refunds match these IDs and exact original item amounts; only the corresponding purchase entitlement is refunded. Partial monetary refunds, pending approvals, disputes and mismatched attribution remain review-only. Item refund coverage is stored separately from licensing state, so an admin-revoked tool cannot incorrectly make an order financially fully refunded. Original invoices and order numbers remain available. Legacy refund/payment processing is preserved through a service-only dispatcher.
- Admin payment review continues using the same intent/event tables. Existing pending list's product_id is the first cart item; the full immutable snapshot is retained server-side. Operator reconciliation for ambiguous attempts remains limited.
