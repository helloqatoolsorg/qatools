1. ARCHITECTURE
===============

The working prototype follows this flow:

Customer / Houdini HDA
        |
        | machine_id + email + purchase_token
        v
FastAPI /activate endpoint
        |
        | validate purchase token
        | build license payload
        | sign payload using PRIVATE KEY
        v
Signed license returned to Houdini
        |
        | save locally
        v
$QATOOLS_SOURCE/qatools_license.txt
        |
        | verify signature using PUBLIC KEY embedded in HDA
        v
HDA allowed to cook

The private key MUST remain on the server.
The HDA only receives/contains the public key.


2. LICENSE FORMAT
=================

The license format is:

qatools|<MACHINE_ID>|PERPETUAL|ALL|1|<BASE64_ED25519_SIGNATURE>

Example structure:

qatools|C8024F075D26B5C8|PERPETUAL|ALL|1|SIGNATURE_HERE

Fields:
1. Vendor: qatools
2. Machine ID
3. License type: PERPETUAL
4. Product scope: currently ALL
5. License version: 1
6. Ed25519 signature encoded as Base64

The server signs everything before the signature:

qatools|MACHINE_ID|PERPETUAL|ALL|1

Houdini reconstructs that payload and verifies the signature with the public key.

6. GENERATING THE ED25519 KEY PAIR
==================================

A fresh Ed25519 key pair was generated during debugging.

Conceptual generate_keys.py:

from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
from cryptography.hazmat.primitives import serialization

private_key = Ed25519PrivateKey.generate()
public_key = private_key.public_key()

private_pem = private_key.private_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PrivateFormat.PKCS8,
    encryption_algorithm=serialization.NoEncryption(),
)

public_pem = public_key.public_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PublicFormat.SubjectPublicKeyInfo,
)

with open("private_key.pem", "wb") as f:
    f.write(private_pem)

with open("public_key.pem", "wb") as f:
    f.write(public_pem)

print("Generated private_key.pem and public_key.pem")

IMPORTANT:
The production private key must never be distributed with the Houdini tool or committed to a public repository.

Because private key material was exposed during development/debugging, a NEW production key pair should be generated before the commercial release. After that, the production private key should be kept secret and backed up securely.

Do not casually regenerate the production key pair after licenses have been issued. Existing licenses depend on the corresponding public/private pair.


7. FINAL LOCAL FASTAPI SERVER
=============================

The working server design was:

from fastapi import FastAPI
from pydantic import BaseModel

import base64
import os

from cryptography.hazmat.primitives import serialization

# ======================================================
# PATHS & KEY LOADING
# ======================================================

BASE_DIR = os.path.dirname(os.path.abspath(__file__))
PRIVATE_KEY_PATH = os.path.join(BASE_DIR, "keys", "private_key.pem")

with open(PRIVATE_KEY_PATH, "rb") as f:
    PRIVATE_KEY = serialization.load_pem_private_key(
        f.read(),
        password=None,
    )

# ======================================================
# CONFIG
# ======================================================

VENDOR_ID = "qatools"
LICENSE_VERSION = 1

# TEMPORARY DEVELOPMENT ALLOWLIST.
# This must eventually be replaced by automatic purchase verification.
VALID_PURCHASE_TOKENS = {
    "TEST-TOKEN-123",
    "QATOOLS-DEMO-001",
}

# ======================================================
# FASTAPI SETUP
# ======================================================

app = FastAPI()


class ActivateRequest(BaseModel):
    machine_id: str
    email: str
    purchase_token: str


# ======================================================
# LICENSE HELPERS
# ======================================================

def build_license_payload(machine_id: str) -> str:
    return "|".join([
        VENDOR_ID,
        machine_id,
        "PERPETUAL",
        "ALL",
        str(LICENSE_VERSION),
    ])


def sign_payload(payload: str) -> str:
    signature = PRIVATE_KEY.sign(payload.encode())
    return base64.b64encode(signature).decode()


# ======================================================
# ROUTES
# ======================================================

@app.get("/")
def root():
    return {"status": "qatools license server running"}


@app.post("/activate")
def activate(data: ActivateRequest):
    # 1. Validate purchase token
    if data.purchase_token not in VALID_PURCHASE_TOKENS:
        return {"error": "invalid_purchase_token"}

    # 2. Build and sign license
    payload = build_license_payload(data.machine_id)
    signature = sign_payload(payload)
    license_key = f"{payload}|{signature}"

    # 3. Return license key
    return {"license_key": license_key}

10. STABLE MACHINE ID
=====================

The final machine-ID approach was:

def get_machine_id():
    import platform
    raw = (
        platform.node()
        + platform.system()
        + platform.machine()
    )
    return hashlib.sha256(raw.encode()).hexdigest()[:16].upper()

One machine ID observed during debugging was:

C8024F075D26B5C8

That value is only an example from the development machine. Never hard-code it.

IMPORTANT:
Once the production machine-ID algorithm is chosen, avoid changing it. Changing the algorithm can make previously generated machine-bound licenses invalid.


11. HOUDINI PYTHONMODULE
========================

The following is the final working architecture used in the HDA PythonModule.

IMPORTANT:
Replace PUBLIC_KEY_PEM below with the EXACT public key matching the server's production private key. Do not copy an old development public key by mistake.

import hou
import os
import json
import base64
import hashlib
import urllib.request
import urllib.error

from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.backends import default_backend

# ======================================================
# CONFIG
# ======================================================

VENDOR_ID = "qatools"
LICENSE_VERSION = "1"

SERVER_URL = "http://127.0.0.1:8000/activate"

QATOOLS_SOURCE = hou.expandString("$QATOOLS_SOURCE")
if not QATOOLS_SOURCE or QATOOLS_SOURCE.startswith("$"):
    raise hou.Error(
        "QATOOLS_SOURCE is not defined.\n"
        "Please install qatools via its Houdini package."
    )

LICENSE_FILE = os.path.normpath(
    os.path.join(QATOOLS_SOURCE, "qatools_license.txt")
)

PUBLIC_KEY_PEM = b"""
-----BEGIN PUBLIC KEY-----
PASTE_THE_PUBLIC_KEY_MATCHING_THE_SERVER_PRIVATE_KEY_HERE
-----END PUBLIC KEY-----
"""

# ======================================================
# MACHINE ID
# ======================================================

def get_machine_id():
    import platform
    raw = (
        platform.node()
        + platform.system()
        + platform.machine()
    )
    return hashlib.sha256(raw.encode()).hexdigest()[:16].upper()

# ======================================================
# LICENSE FILE IO
# ======================================================

def _load_license():
    if not os.path.exists(LICENSE_FILE):
        return None

    with open(LICENSE_FILE, "r", encoding="utf-8") as f:
        return f.read().strip()


def _save_license(license_key: str):
    os.makedirs(os.path.dirname(LICENSE_FILE), exist_ok=True)

    with open(LICENSE_FILE, "w", encoding="utf-8") as f:
        f.write(license_key.strip())

# ======================================================
# LICENSE VERIFICATION
# ======================================================

def _verify_license(license_key: str) -> bool:
    try:
        parts = license_key.split("|")

        if len(parts) != 6:
            return False

        vendor, machine_id, scope, products, version, signature_b64 = parts

        if vendor != VENDOR_ID:
            return False

        if version != LICENSE_VERSION:
            return False

        if machine_id != get_machine_id():
            return False

        payload = "|".join(parts[:-1])
        signature = base64.b64decode(signature_b64)

        public_key = serialization.load_pem_public_key(
            PUBLIC_KEY_PEM,
            backend=default_backend()
        )

        public_key.verify(
            signature,
            payload.encode("utf-8")
        )

        return True

    except Exception:
        return False


def is_license_valid() -> bool:
    key = _load_license()

    if not key:
        return False

    return _verify_license(key)

# ======================================================
# SOP ENFORCEMENT
# ======================================================

def require_license_or_fail():
    if not is_license_valid():
        raise hou.NodeError(
            "qatools license not activated.\n"
            "Please activate the tool."
        )

# ======================================================
# ONLINE ACTIVATION
# ======================================================

def activate_online(node):
    email_parm = node.parm("email")
    token_parm = node.parm("purchase_token")

    if email_parm is None or token_parm is None:
        hou.ui.displayMessage(
            "Activation parameters not found on this node.",
            severity=hou.severityType.Error
        )
        return

    email = email_parm.eval().strip()
    token = token_parm.eval().strip()

    if not email or not token:
        hou.ui.displayMessage(
            "Please enter Email and Purchase Token.",
            severity=hou.severityType.Error
        )
        return

    payload = {
        "machine_id": get_machine_id(),
        "email": email,
        "purchase_token": token,
    }

    try:
        req = urllib.request.Request(
            SERVER_URL,
            data=json.dumps(payload).encode(),
            headers={"Content-Type": "application/json"},
            method="POST",
        )

        with urllib.request.urlopen(req, timeout=10) as resp:
            data = json.loads(resp.read().decode())

    except urllib.error.URLError as e:
        hou.ui.displayMessage(
            f"License server unreachable:\n{e}",
            severity=hou.severityType.Error
        )
        return

    if "error" in data:
        hou.ui.displayMessage(
            f"Activation failed:\n{data['error']}",
            severity=hou.severityType.Error
        )
        return

    license_key = data.get("license_key")

    if not license_key:
        hou.ui.displayMessage(
            "Invalid response from license server.",
            severity=hou.severityType.Error
        )
        return

    _save_license(license_key)

    hou.ui.displayMessage(
        "qatools activated successfully.\n"
        "Please recook or re-place the node.",
        severity=hou.severityType.Message
    )


12. PYTHON SOP LICENSE GUARD
============================

A Python SOP is placed at the beginning of the internal SOP network.

Its code is:

hou.pwd().parent().hdaModule().require_license_or_fail()

Behavior:
- No valid license -> raises hou.NodeError and stops the HDA from cooking.
- Valid license -> code returns normally and the rest of the SOP network can cook.

We deliberately did NOT use hou.time() as a dependency because we did not want the licensing mechanism to force time-dependent cooking/evaluation.

The HDA UI/parameters should remain accessible so the user can enter activation information even when the internal SOP network is blocked.


13. ACTIVATE BUTTON CALLBACK
============================

The HDA's activation button can call:

hou.pwd().hdaModule().activate_online(hou.pwd())

Expected HDA parameter internal names:

email
purchase_token

The activate_online() function checks whether these parameters exist before evaluating them.


14. THE CRITICAL HOUDINI CRYPTOGRAPHY BUG
=========================================

During debugging, everything appeared correct:
- License file existed
- Payload parsed correctly
- Vendor matched
- Version matched
- Machine ID matched
- Base64 signature decoded correctly

But is_license_valid() still returned False.

A verbose verifier revealed:

TypeError("load_pem_public_key() missing 1 required positional argument: 'backend'")

Houdini's bundled Python/cryptography environment required an explicit backend.

The fix was:

from cryptography.hazmat.backends import default_backend

public_key = serialization.load_pem_public_key(
    PUBLIC_KEY_PEM,
    backend=default_backend()
)

This was an important compatibility difference between the normal server Python environment and Houdini's embedded Python environment.


15. KEY-PAIR MISMATCH PROBLEM
=============================

Another major debugging issue was key drift.

During development, new Ed25519 key pairs were generated. This meant that at various points:

- server private key = NEW key
- HDA public key = OLD key
- cached license = signed with another/older key

Even if every other license field is correct, signature verification MUST fail when the public and private keys are not from the same key pair.

The final successful state required:

1. One matching Ed25519 key pair.
2. Server using that private_key.pem.
3. HDA embedding that pair's exact public_key.pem.
4. Old cached licenses deleted.
5. Server restarted.
6. HDA updated/saved.
7. Activation performed again.

Then verification succeeded.

18. WHAT THE SUCCESSFUL ACTIVATION PROVED
=========================================

Once everything matched, the working sequence proved that:

1. Houdini generated a machine ID.
2. Houdini contacted the FastAPI server.
3. Server accepted the temporary purchase token.
4. Server constructed the license payload.
5. Server signed it using Ed25519 private key.
6. Server returned the signed license.
7. Houdini wrote qatools_license.txt.
8. Houdini reconstructed the signed payload.
9. Houdini loaded the matching public key.
10. Ed25519 verification succeeded.
11. is_license_valid() returned True.
12. Python SOP stopped raising the licensing error.
13. HDA cooked normally.


19. WHY PREVIOUS ATTEMPTS FAILED
================================

There was not just one issue.

The main problems encountered were:

A. SERVER PRIVATE KEY PATH
--------------------------
The server attempted to load private_key.pem from the wrong working directory.

Fixed by constructing the absolute path relative to server.py.

B. HOUDINI CRYPTOGRAPHY COMPATIBILITY
-------------------------------------
Houdini required backend=default_backend() when loading the PEM public key.

Without debug output, this exception was swallowed and simply appeared as is_license_valid() == False.

C. KEY PAIR DRIFT
-----------------
At some stages, the server's private key and Houdini's embedded public key did not correspond to the same generated pair.

Any license signed under an old/different private key also became invalid against the current public key.

D. CACHED OLD LICENSES
----------------------
After changing keys or machine-ID behavior, an old qatools_license.txt could remain on disk. It needed to be deleted and generated again through activation.

E. DEBUGGING HIDING EXCEPTIONS
------------------------------
The production verifier intentionally did:

except Exception:
    return False

This is fine for end users, but terrible for development because it hides the actual reason verification failed.

The verbose debug verifier exposed the real exception.


20. SECURITY MODEL
==================

SERVER:
- Contains PRIVATE KEY.
- Validates proof of purchase.
- Signs licenses.

HDA / CUSTOMER MACHINE:
- Contains PUBLIC KEY only.
- Cannot legitimately generate new signed licenses without the server private key.
- Verifies locally cached licenses.

This means activation requires the server, but after successful activation the current PERPETUAL license can be validated locally without contacting the server every time the tool cooks.

This is intentional: do NOT make a network request every time the HDA cooks.

23. MARKETPLACE GOAL
====================

The larger goal is a QATOOLS website/marketplace where tools can be sold separately.

Example:

Tool B         -> separate product

24. CLOUD SERVER — NEXT MAJOR STEP
==================================

Currently the activation server is the developer's PC:

http://127.0.0.1:8000/activate

That obviously cannot be used by customers.

The next planned step is to deploy the same FastAPI application to a low-maintenance cloud service.

Railway was discussed as a simple candidate because the application is tiny:
- FastAPI
- one/few endpoints
- very low CPU requirements
- no GPU
- low activation traffic
- HTTPS required

Once deployed, Houdini changes from:

SERVER_URL = "http://127.0.0.1:8000/activate"

to something like:

SERVER_URL = "https://YOUR-LICENSE-SERVER/activate"

The exact provider/domain should be chosen based on current pricing and requirements rather than assuming Railway is permanently the best option.


25. PAYMENT PROVIDER DISCUSSION
===============================

Gumroad was discussed because a merchant-of-record/storefront style service can reduce maintenance around:
- payments
- VAT/sales tax handling (depending on provider/terms)
- receipts
- refunds
- checkout

However, Gumroad is NOT technically required by the licensing system.

The important architectural requirement is simply:

SERVER MUST HAVE A RELIABLE WAY TO VERIFY THAT A CUSTOMER PURCHASED PRODUCT X.

Possible payment/store approaches can include:
- Gumroad
- Lemon Squeezy
- Paddle
- Stripe + own tax/business infrastructure
- another marketplace/payment provider

The licensing server should ideally keep the purchase-provider logic separated from the cryptographic license-signing logic so providers can be changed later without rewriting the HDA license verification system.


26. WHAT “AUTOMATIC” MEANS
===========================

The final system should NOT require manually entering each customer's token into server.py.

Instead:

Customer purchases
    -> provider creates purchase record/token
    -> customer activates
    -> QATOOLS server asks provider whether purchase is valid
    -> if valid, QATOOLS server signs license automatically

The developer does nothing for a normal activation.

The current VALID_PURCHASE_TOKENS set is only a development stand-in for that future API/database check.


27. RECOMMENDED SEPARATION OF RESPONSIBILITIES
==============================================

For the next version, keep these layers separate:

A. PAYMENT LAYER
- Determines whether customer owns Tool A / Tool B / etc.

B. LICENSE SERVER
- Receives activation request.
- Calls/verifies payment layer.
- Applies activation rules.
- Builds payload.
- Signs payload.

C. HOUDINI CLIENT
- Sends activation request.
- Saves returned signed license.
- Verifies signature locally.
- Checks machine/product/version.
- Enables or blocks the tool.

This separation will make changing Gumroad/Stripe/etc. much easier later.


28. THINGS TO HARDEN BEFORE PRODUCTION
======================================

Before selling publicly, review at least:

- Generate a NEW production Ed25519 key pair because development private-key material was exposed during debugging.
- Store production private key as a secure cloud secret/environment secret rather than in a public Git repository.
- Add HTTPS (normally handled by cloud host/reverse proxy).
- Do not expose debug exceptions/private data to customers.
- Add product IDs instead of relying on ALL.
- Decide activation limits / machine replacement policy.
- Decide refund/revocation behavior.
- Decide whether perpetual licenses remain valid after refunds (normally they should not, but local perpetual caching complicates revocation).
- Add rate limiting/basic abuse protection if necessary.
- Validate server responses carefully.
- Consider logging activation events without storing unnecessary personal information.
- Decide whether email is truly required by the licensing protocol or only used for purchase matching/support.
- Back up the production private key securely.
- Have a recovery/key-rotation strategy before release.


29. IMPORTANT DESIGN TRADEOFF: PERPETUAL OFFLINE CACHE
======================================================

The current architecture intentionally allows this:

Online activation once
        -> signed license cached locally
        -> future verification happens locally
        -> cloud server can be temporarily unavailable
        -> tool still works

This is excellent for customer reliability and low server load.

But it also means the server cannot instantly revoke an already issued perpetual license unless the HDA periodically contacts the server or the license has an expiry/revalidation mechanism.

This should be consciously decided before commercial release, especially for refunds/chargebacks.
