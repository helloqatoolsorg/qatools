# Portable authoring utility for Houdini 21 and 22

Owner request, 4 November 2026: same-named exports replace automatically; provide portable kits for 21 and 22. The owner clarified that Houdini 21 is on another computer: do not install the H21 utility or application on this computer.

## Files

Generated by `powershell -NoProfile -ExecutionPolicy Bypass -File houdini/authoring/build-portable.ps1`:

- houdini/dist/qatools-authoring-houdini21.zip
- houdini/dist/qatools-authoring-houdini22.zip

Extract the appropriate ZIP, run its Install Houdini 21.cmd or Install Houdini 22.cmd, restart Houdini and enable the qatools dev shelf tab. Keep the extracted files together until installation finishes. The kit contains four authoring Python files, shelf, installer, version-specific command file, readme and hash manifest. No source HDAs, customer runtime, account cache, credentials, private keys or database content is bundled. Rebuild after future authoring changes. ZIP artifacts are ignored by Git.

Both installers place the same pure-Python modules at packages/qatools-authoring/scripts/python/qatools_authoring, avoiding a hard-coded Python 3.13 directory. A prior python*libs/qatools_authoring module is moved into a verified backup path inside the package so it cannot shadow the new modules. Existing shelf identity is retained. Custom preferences can be selected with -HoudiniPreferences using an absolute path.

Houdini 22 authoring was updated on this computer; restart is required. Houdini 21 was not installed here. The installer was tested against isolated temporary 21/22 preference folders, including repeat installation, file integrity and preserving old modules. That is not native Houdini 21 validation. The current GUI utility targets Qt6/PySide6 builds, with a clear error for other builds. Pure authoring files parse under Python 3.11 syntax. The worker always uses the running Houdini installation's hython.

## ZIP replacement

Filenames are still derived automatically from the development Internal Name. QA_Tool_Name_dev.hdalc stays editable and unchanged; only the exported QA_Tool_Name.hdalc is black-boxed inside QA_Tool_Name.zip. The complete new ZIP is written/flushed to a temporary sibling before atomic replacement. A failed HDA build, failed write or locked destination retains the prior complete export. No loose release HDA overwrites the development library. Separate export folders should be used when maintaining different Houdini builds with the same canonical filename.

Export setup no longer requires the customer licensing module merely to create an archive. Missing retail runtime yields safe inactive/default UI fields during preparation. Using an exported tool still requires the complete compatible customer package; the guard remains enforced.

## Website UI

The editor fetches only selected ZIP metadata and displays the filename and replacement control. It no longer downloads/inspects ZIP contents for that display. Publication/file/identity validation is retained. Both Dashboard and License Data use the shared AccountActivationKey component: Replace key and its confirmation/management controls are removed. Create a first key, Reveal, Hide and Copy remain. Older unrecoverable keys show a support message. The secure backend rotation API is retained for recovery; it is not exposed by this UI.
