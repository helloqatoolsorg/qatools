## Transfer test order

1. Confirm second computer can reach the chosen website backend and client trusts its public signing key.
2. Confirm attempting activation on the second computer while the first is assigned fails with the one-computer rule. Use the same existing account key privately; do not replace it.
3. Release the first computer through the website admin account-machine action. Ownership/history should remain.
4. Refresh on the first computer while connected; verified release should block the HDA. The first offline computer may retain authorization until its cached proof expires, as already approved.
5. Activate the second computer once; all currently owned tools should share that assignment. Check cooking and offline recooking there.
6. If returning to the first computer, repeat the explicit admin release and activation sequence. Automatic renewal must never reclaim a released assignment.

This package preparation does not perform a live release or transfer. The first machine's current license/cache was not changed.
